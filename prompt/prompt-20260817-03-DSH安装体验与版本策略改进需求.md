## 1. 文档信息

- 文档类型：后续设计、开发与验收执行 Prompt
- 适用项目：DeepSeek Harness Desktop
- 编写日期：2026-08-17
- 需求状态：待实现
- 需求来源：Windows 空白环境首次安装实测反馈
- 关联计划：`plan/plan-20260817-03-DSH安装体验与版本策略改进计划.md`

## 2. 使用方式

将本文作为后续设计、实现和验收任务的完整输入。执行者必须先读取当前实现、项目文件、相关测试、`AGENTS.md`、`CLAUDE.md`、`code_rule.md`、开发文档、详细设计和阶段 7 验证记录，再依据实际类型与接口实施，不得仅根据本文猜测代码结构。

本需求来自真实空白电脑安装问题：桌面应用内首次准备 DSH 未能顺利完成，而用户最终通过可见终端手动执行 `npx @deepseek-ai/dsh web` 完成下载和启动。现有实现存在以下缺口：

1. npx 下载、进程启动和健康检查共用笼统状态，用户无法判断当前阶段和失败位置。
2. 首次无缓存下载被包含在默认 60 秒启动期限内，慢速网络下可能尚未下载完成就被宿主终止。
3. 引导缺少完整的手动操作步骤、可复制命令和直达官方资料的快捷入口。
4. 自动 npx 路径固定 `@deepseek-ai/dsh@0.1.0-rc.6`，无法跟随快速迭代的 DSH 发布节奏。
5. Node.js 在桌面应用启动后安装时，当前进程继承的 PATH 可能仍是旧值，重新检查可能误报 Node.js/npx 缺失。

## 3. 目标与非目标

### 3.1 目标

1. 在安装引导中持续显示可理解、可诊断、已脱敏的详细过程日志。
2. 显示当前操作的实时耗时、阶段和 5 分钟总期限，用户可以随时取消。
3. 提供不依赖桌面自动流程的手动安装/启动说明、可复制命令和官方快捷链接。
4. 自动 npx 启动不再固定 DSH 版本，使用 npm 对 `@deepseek-ai/dsh` 的当前解析结果。
5. 保持现有 Owned DSH、Job Object、状态机、generation、loopback 身份检查和 WebView2 安全边界。
6. 在真实 Windows 空白用户环境验证首次无缓存下载，而不是只在已有开发缓存的机器验收。

### 3.2 非目标

- 不在宿主内静默安装 Node.js，不提升权限，不调用系统级包管理器。
- 不执行 `npm install -g`，不把 DSH 全局安装到系统。
- 不扫描、硬编码或直接修改 npm `_npx` 缓存目录。
- 不接受用户输入的任意 Shell 文本，不放宽自定义 `.cmd`、`.bat` 或命令行边界。
- 不因手动引导而停止、重启或接管用户在外部终端启动的 DSH。
- 不移除服务身份验证、loopback 限制或 WebView2 同源约束。
- 不承诺未来所有 DSH 版本永远兼容；兼容性失败必须可诊断、可重试并有手动路径。

## 4. 产品决策

### 4.1 自动启动命令

当未发现可用全局 `dsh.cmd` 且 Node.js/npx 可用时，桌面应用的内置命令调整为：

```powershell
npx -y @deepseek-ai/dsh web
```

约束如下：

- 包名仍固定为官方 `@deepseek-ai/dsh`，但不得附加固定版本号或 dist-tag。
- `-y` 仅用于消除隐藏控制台中的首次确认，不代表全局安装。
- `web` 和合法的数值端口仍由应用生成，不能来自用户 Shell 文本。
- `.cmd` 继续只通过 `CmdCommandLineBuilder` 的受控模板执行。
- 工作目录继续通过 `ProcessStartInfo.WorkingDirectory` 传递。
- npm registry、代理和证书策略沿用当前 Windows 用户的 npm 配置；日志不得输出其中的凭据。

全局 `dsh.cmd` 路径仍可优先使用，其实际版本应通过诊断尽可能显示。不得为了“不固定版本”而自动升级或覆盖用户已有的全局 DSH。

### 4.2 五分钟期限

- 用户确认“准备并启动”后，从操作开始到 DSH 身份确认成功的总期限为 5 分钟。
- 该期限包含 npx 包解析、首次下载、缓存准备、DSH 进程创建和 HTTP 身份检查。
- UI 必须明确显示“最长等待 5 分钟”，不能仍显示 60 秒或只写“请稍候”。
- 到达期限后使用稳定错误码报告超时，记录最后阶段和总耗时，并回收本次 Owned 进程树。
- 用户取消、应用退出和新生命周期操作仍应立即取消，不需要等待 5 分钟结束。
- v1 配置没有“是否由用户主动修改”的来源标记，无法区分历史默认 60 秒与用户手工填写的 60 秒。采用确定性取舍：所有 v1 `StartupTimeoutSeconds == 60` 均迁移为 300，接受覆盖极少数有意设置；其他处于合法范围内的值原样保留，并在升级说明中公开该行为。
- 迁移必须采用统一管线“读取 JSON → 按 `schemaVersion` 迁移到当前结构 → 反序列化 → 验证”，并发生在拒绝旧 schema 之前；主配置和 `.bak` 恢复必须复用同一管线，不能因主文件损坏而漏迁移备份或丢失工作目录。
- 如果后续向用户开放超时编辑，必须新增显式来源或设置语义，不能再依赖数值猜测用户意图。

### 4.3 实时耗时

安装引导至少显示：

- 当前阶段名称，例如“检查环境”“准备 npm 包”“启动 DSH”“验证本机服务”。
- 当前阶段耗时和总耗时，推荐格式 `00:00 / 05:00`。
- 计时模型必须同时记录操作总起始单调时刻与当前阶段起始单调时刻；阶段切换时结算上一阶段耗时、写入阶段摘要，并把阶段计时重置为零，总耗时继续累计。
- 操作开始时间不需要显示完整日期；日志行保留本地时间戳。
- 使用单调时钟计算耗时，不能依赖系统时间回拨。
- 显示至少每秒刷新一次，但不得每秒向日志缓冲区写一行。
- 操作结束、取消、失败、超时或 ViewModel 释放时，计时任务和取消令牌必须成对释放。

耗时更新必须切回 WPF Dispatcher，不允许后台线程直接更新绑定属性，也不得在 UI 线程阻塞等待。

### 4.4 详细过程日志

安装引导中的日志必须覆盖宿主阶段日志和子进程 stdout/stderr，而不只是显示 npm 原始输出。

至少记录以下事件：

| 阶段 | 必须记录的内容 |
| --- | --- |
| 环境检查 | 检查开始/结束、WebView2/Node.js/npx/全局 DSH 的分类结果、可安全显示的版本与可执行文件名 |
| PATH 处理 | 当前进程未发现新安装 Node.js 时的明确提示；重新检查是否使用了刷新后的用户/系统 PATH |
| 用户确认 | 用户已确认、用户取消；不得记录窗口内容或其他隐私数据 |
| 命令准备 | 安全模板 `npx -y @deepseek-ai/dsh web`、工作目录、目标 loopback 地址、5 分钟期限 |
| 进程创建 | 开始创建、成功后的 PID、立即退出及退出码 |
| npm/npx | 经过规范化、限长和脱敏的 stdout/stderr，保留 npm 错误代码与阶段信息 |
| 健康检查 | 开始探测、等待服务、识别到输出地址、身份确认成功或最终失败；避免每次轮询刷屏 |
| 收尾 | 成功、失败、取消、超时、进程树回收结果与总耗时 |

日志显示要求：

- 每行至少包含时间、来源或级别和文本，例如 `[14:05:22] [desktop] 开始准备 DSH`。
- UI 日志缓冲区必须有界，容量应足以保留一次完整首次安装过程；达到上限时只淘汰最旧记录。
- 底层 `RecentLogBuffer` 与安装 UI 不得各自维护互不相关的容量常量。实施时使用同一集中容量来源，安装 UI 不再用更小的第二上限提前淘汰底层仍保留的记录；数值由真实首次安装输出验证后冻结。
- 日志区自动跟随最新输出，同时允许用户向上滚动查看历史；用户主动查看历史时不得强制抢回滚动位置。
- 提供“复制日志”或等价操作；复制前仍执行脱敏，不复制不可见的完整环境变量。
- 关键摘要应同步写入按日滚动的应用文件日志，但 npm 外部文本必须经过统一规范化、限长和脱敏。
- Authorization、Cookie、Token、Secret、代理凭据、registry 用户信息、完整环境变量和 API Key 不得进入 UI、文件日志、异常或测试快照。

### 4.5 失败分类与恢复

不能把首次准备中的所有失败都显示为“DSH 启动超时”。至少应让用户区分：

- Node.js/npx 缺失或 PATH 尚未刷新。
- npm DNS、代理、TLS/证书、registry、权限或包解析失败。
- npx/DSH 进程立即退出及退出码。
- 五分钟期限耗尽。
- 端口占用或已存在身份未知的服务。
- DSH 已启动但输出或页面身份与预期不匹配。

稳定的 npm 错误码可以用于生成操作建议；未知 stderr 不得通过脆弱文本猜测成确定原因。已有 `DSH-E*` 含义不得无迁移改变，新增错误语义需要同步详细设计、安装文档和测试。

失败后必须保留：

- 当前错误码和简明中文说明。
- 最后阶段、总耗时及有界的详细日志。
- “重试”“复制日志”“手动安装”“打开官方资料”和“返回”操作。

### 4.6 PATH 刷新

当用户在桌面应用运行期间安装 Node.js 后点击“重新检查”时，应重新读取 Windows 当前用户和系统环境中的 PATH，并形成仅用于受控依赖解析的新搜索路径。不得依赖应用启动时继承的旧 Process PATH。

实现必须满足：

- 正确合并 Machine PATH 与 User PATH，去重时使用 Windows 路径比较语义。
- 不记录完整 PATH，不把环境字典直接写入日志。
- 不修改机器或用户环境变量。
- 解析到的 `node.exe`、`npx.cmd` 和 `dsh.cmd` 仍需经过现有文件存在性与脚本安全校验。
- 如果刷新后仍不可用，提示用户重启桌面应用或 Windows 会话，并保留手动验证命令。

### 4.7 手动安装与快捷操作

安装引导必须提供可展开或独立的“手动安装”区域，步骤应能在空白 Windows 10/11 x64 环境直接执行：

1. 打开 Node.js 官方下载页并安装当前 LTS x64 版本。
2. 安装完成后重新打开终端；如果桌面应用仍未识别，点击“重新检查”或重启桌面应用。
3. 在 PowerShell 中验证：

   ```powershell
   node --version
   npx --version
   ```

4. 进入需要作为工作目录的文件夹，执行官方无版本命令：

   ```powershell
   npx @deepseek-ai/dsh web
   ```

5. 首次出现 npx 安装确认时按提示确认；等待终端显示本机服务地址，并保持该终端运行。
6. 返回桌面应用，使用默认地址 `http://127.0.0.1:3080/` 连接。该实例视为 `RunningExternal`，桌面应用不得停止或重启它。

必须提供以下快捷操作：

- “复制手动命令”：复制固定常量 `npx @deepseek-ai/dsh web`，不接受用户拼接参数。
- “打开 PowerShell”：打开可见终端，默认工作目录为当前已验证工作区，但不自动执行命令。
- “Node.js 下载”：系统浏览器打开 Node.js 官方 HTTPS 页面。
- “DSH 官方文档”：系统浏览器打开官方文档或仓库。
- “npm 包页面”：系统浏览器打开 `@deepseek-ai/dsh` 官方 npm 页面。

剪贴板和终端启动应通过可替换服务抽象实现，ViewModel 不直接调用静态 Clipboard 或创建 Process。打开终端失败时给出可恢复提示，不影响自动安装状态。

### 4.8 不固定版本后的关于与更新语义

删除“已验证固定版本”“当前固定版本”等不再真实的 UI 和文档表达。关于窗口应区分：

- 当前检测到的全局 DSH 版本，若无法取得则显示“未知”。
- 自动 npx 路径使用 npm 当前解析版本，不在桌面配置中锁定版本。
- npm 当前 `latest` 仅作为信息展示；不再与一个不存在的固定版本比较“可更新”。

可以保留手动查询 npm `latest` 的能力，但结果不得持久化为启动版本，也不得在后台静默请求。若现有更新模型强依赖 `VerifiedVersion`，应重构或删除无意义字段和分支，不保留误导性死代码。

## 5. 系统与安全边界

1. 自动路径创建的 DSH 必须继续加入带 `KILL_ON_JOB_CLOSE` 的 Windows Job Object。
2. 手动终端创建的 DSH 仅按健康检查连接为外部实例，不能转为 Owned，也不能因端口相同被结束。
3. Start/Stop/Restart、取消和地址应用继续由生命周期单操作门、operation token 和 generation 串行保护。
4. 5 分钟等待不能扩大 HTTP 单次探测超时、响应大小或重定向范围。
5. 服务地址仍只能是经过验证的 loopback HTTP/HTTPS URI；可达但身份未知的服务不得加载。
6. 不因 npx 使用 latest 而放开 npm 包名、Shell 参数、registry URL 或执行入口。
7. 外部日志进入 UI 前必须经过 `OutputLineProcessor` 规范化与限长，并在进入缓冲区前脱敏；文件日志继续经过 `SensitiveDataRedactor`。
8. 计时器、事件订阅、CTS、SemaphoreSlim、Process 和 Job Object 必须在成功、失败、取消和退出路径成对释放。

## 6. UI 与可访问性要求

- 安装引导仍是主窗口内容模式，不新增独立业务窗口层级。
- 阶段、耗时、剩余上限和结果不能只用颜色表示。
- 日志区应具有稳定高度、垂直滚动和文本换行，不因长 npm 输出挤压底部操作区。
- “取消”仅在自动准备进行中可用；“准备并启动”在依赖可用且无操作运行时可用。
- 手动说明可折叠，但失败时入口必须保持可见。
- 复制、终端和官方链接按钮应有清晰图标、ToolTip 与 Automation Name。
- 820x600 以及 100%、125%、150%、200% DPI 下，阶段、计时、日志和操作按钮不得重叠或被 WebView2 覆盖。
- 键盘用户能够访问日志、复制命令、打开终端、重试和取消；焦点不能被后台日志更新抢走。

## 7. 验收标准

### 7.1 日志与耗时

- `AC-INSTALL-LOG-001`：开始自动准备后立即出现环境、命令、工作目录、目标地址和期限的宿主日志。
- `AC-INSTALL-LOG-002`：npx stdout/stderr 实时显示，日志带时间和来源，敏感值被脱敏且单行有限长。
- `AC-INSTALL-LOG-003`：成功、失败、取消和超时均记录阶段、退出码或错误码、回收结果及总耗时。
- `AC-INSTALL-LOG-004`：UI 和文件日志均有界；复制日志不泄露凭据、完整环境变量或未脱敏外部文本。
- `AC-INSTALL-TIME-001`：操作期间每秒更新当前阶段耗时和总耗时；阶段切换时上一阶段被结算且新阶段从零开始，总耗时连续累计，不每秒写日志。
- `AC-INSTALL-TIME-002`：首次无缓存下载可等待至 5 分钟；历史默认 60 秒配置升级后不会提前终止。
- `AC-INSTALL-TIME-003`：取消和退出可立即结束等待并回收 Owned 进程树，不残留计时任务。

### 7.2 手动路径

- `AC-INSTALL-MANUAL-001`：无 Node.js 的用户能从引导直达官方 LTS 下载页并看到重检/重启说明。
- `AC-INSTALL-MANUAL-002`：复制命令精确为 `npx @deepseek-ai/dsh web`，剪贴板失败可恢复且不执行 Shell。
- `AC-INSTALL-MANUAL-003`：打开 PowerShell 使用当前合法工作目录并保持可见，不自动执行命令，不接受用户 Shell 文本。
- `AC-INSTALL-MANUAL-004`：手动启动的服务只连接为 `RunningExternal`，停止和重启命令不可用。
- `AC-INSTALL-MANUAL-005`：Node.js、官方 DSH 文档和 npm 包链接均使用固定 HTTPS 地址交给系统浏览器。

### 7.3 非固定版本

- `AC-INSTALL-VERSION-001`：自动 npx 参数精确为 `-y @deepseek-ai/dsh web`，不包含 `@<version>` 或 dist-tag。
- `AC-INSTALL-VERSION-002`：端口非 3080 时只追加 `--port <1-65535>`，其他用户参数仍被拒绝。
- `AC-INSTALL-VERSION-003`：关于窗口、安装引导、确认框和文档不再宣称固定或已验证 DSH 版本。
- `AC-INSTALL-VERSION-004`：手动 npm latest 查询不改变启动参数、不自动安装、不持久化版本。
- `AC-INSTALL-VERSION-005`：DSH latest 发生变化后无需发布新 Desktop 即可由 npx 自动路径解析，但身份检查失败时仍拒绝加载。

### 7.4 PATH 与故障恢复

- `AC-INSTALL-PATH-001`：应用启动后安装 Node.js，再点击重新检查，可从刷新后的 Machine/User PATH 发现 node 和 npx。
- `AC-INSTALL-PATH-002`：PATH 合并不修改系统环境、不记录完整 PATH，并正确处理空项、引号、重复项和无权访问目录。
- `AC-INSTALL-FAIL-001`：DNS、TLS、registry、权限、立即退出、超时和端口身份冲突提供不同的可操作提示。
- `AC-INSTALL-FAIL-002`：失败后日志和手动入口保留，重试不会创建并行 npx 或复用过期 generation。

## 8. 测试要求

### 8.1 单元测试

- npx 无版本参数、默认端口和非默认端口的精确参数测试。
- `.cmd` 模板对空格、引号、`& | < > ^ % ! ( )`、中文路径和非法附加参数的安全回归测试。
- Machine/User PATH 合并、去重、安装后刷新和不记录完整 PATH 测试。
- 300 秒默认值、v1 中 60 一律迁移为 300、其他合法值保留、非法超时值和原子保存测试；显式覆盖“主文件损坏、`.bak` 仍为 v1”的恢复迁移。

## 10. 完成定义

只有同时满足以下条件，需求才可标记完成：

1. 四项用户需求均有实现、自动测试和真实空白环境验证证据。

5. 手动步骤、复制命令、PowerShell 和官方链接可从安装失败状态直接访问。
6. 手动 DSH 仍是外部实例，Owned/External 所有权边界未被破坏。
7. PATH 刷新不修改系统环境，不泄露完整环境变量。
8. UnitTests、IntegrationTests 和完整发布门禁全部通过，0 warning、0 error。
9. 相关文档、版本、manifest、验证记录和发布 README 与实际行为一致。
10. 未提交 `bin/`、`obj/`、`TestResults/`、日志、npm 缓存、WebView2 数据或凭据。
