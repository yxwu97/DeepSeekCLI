# DSH 安装体验、过程可观测性与版本策略改进开发计划

## 1. 计划信息

- 计划编号：03
- 编写日期：2026-08-17
- 需求来源：`prompt/prompt-20260817-03-DSH安装体验与版本策略改进需求.md`
- 实施状态：代码与发布门禁已完成；空白 Windows 虚拟机验证因本机无可用 VM/镜像而阻塞
- 目标版本：下一个兼容功能版本，实施时按当前 `AppVersion` 递增 minor
- 适用基线：Desktop 0.3.0 及其后续文档修订

## 2. 实施目标

本计划落实四项要求：

1. 安装过程显示详细、实时、可复制且已脱敏的日志。
2. 显示阶段耗时与总耗时，并将首次准备期限延长到 5 分钟。
3. 提供手动安装步骤、复制命令、打开 PowerShell 和官方快捷链接。
4. 自动 npx 启动不固定 DSH 版本，跟随 npm 当前解析版本。

实施必须遵守 `AGENTS.md`、`CLAUDE.md` 和 `code_rule.md`。特别保留 Owned 进程 Job Object、生命周期串行、generation 校验、结构化参数、外部实例只连接、loopback 身份检查、外部文本限长脱敏及资源成对释放。

## 3. 当前实现基线

### 3.1 已有能力

- `InstallationGuideViewModel` 支持重新检查、确认后启动、取消和最多 200 行进程日志。
- `HarnessProcessManager` 异步读取 stdout/stderr，并把规范化输出写入 `IRecentLogBuffer`。
- `HarnessLifecycleCoordinator` 统一负责预检、Owned 进程创建、健康等待、取消、失败和 generation 防护。
- `DshCommandResolver` 优先解析全局 `dsh.cmd`，否则解析 `npx.cmd`。
- `CmdCommandLineBuilder` 对 `.cmd` 使用受控参数模板和系统 `cmd.exe`。
- `DependencyDiagnosticsService` 检查 WebView2、全局 DSH、Node.js 和 npx。
- `ExternalLinkLauncher` 只打开固定官方资源或合法 HTTP(S) URI。

### 3.2 已确认缺口

| 缺口 | 当前代码表现 | 影响 |
| --- | --- | --- |
| 首次下载超时 | `StartupTimeoutSeconds` 默认 60，下载与健康等待共用期限 | 空缓存和慢网络可能提前终止 |
| PATH 不刷新 | 诊断与解析读取当前 Process PATH | 运行期间安装 Node.js 后可能仍识别不到 |
| 日志不完整 | UI 主要接收子进程输出，缺少宿主阶段与收尾摘要 | 用户无法定位卡点 |
| 无耗时显示 | 安装 ViewModel 没有单调计时状态 | 用户不知道等待多久或剩余上限 |
| 手动帮助不足 | 只有 Node.js 下载链接和“下载并启动” | 自动失败后缺少自救路径 |
| 固定 DSH | 参数为 `@deepseek-ai/dsh@0.1.0-rc.6` | Desktop 发布节奏绑定 DSH 发布 |
| 更新语义失真 | 关于窗口把 npm latest 与 `VerifiedVersion` 比较 | 取消固定版本后模型不再成立 |
| 文件诊断不足 | 进程输出只在内存 UI 缓冲，文件日志缺少关键摘要 | 关闭界面后难以追踪首次失败 |

阶段 7 验证记录已明确将“未安装 Node.js、无 npm 缓存的干净环境”列为尚需外部验证，本计划必须补齐该门禁。

## 4. 冻结设计决策

### 4.1 命令与版本

- 自动 npx 参数固定为结构化列表：`-y`、`@deepseek-ai/dsh`、`web`，不包含版本或 dist-tag。
- 手动命令固定为可复制文本：`npx @deepseek-ai/dsh web`。
- 非默认端口只允许由 `ServiceUri` 追加 `--port` 和 1-65535 数值。
- 保留全局 `dsh.cmd` 优先策略，不自动覆盖用户全局安装。
- 删除 `VerifiedVersion` 作为启动依据；npm latest 仅用于信息展示。

### 4.2 期限与迁移

- 自动准备总期限为 300 秒，从用户确认后的启动操作开始，到 DSH 身份确认成功为止。
- 将 `AppSettings.StartupTimeoutSeconds` 新默认值改为 300。
- 递增 `SchemaVersion`。由于 v1 没有超时值来源标记，确定性地把所有 v1 `StartupTimeoutSeconds == 60` 迁移为 300，接受覆盖极少数用户有意手工设置；其他 5-300 范围内的合法值原样保留。
- 迁移采用统一前置管线“读取 JSON → 按 schema 迁移 → 反序列化 → 验证”，必须在当前版本校验拒绝 v1 之前运行；主文件与 `.bak` 恢复路径复用同一入口。
- 生产使用 300 秒，测试通过可注入期限/时钟缩短等待，禁止自动测试真实等待 5 分钟。
- 单次 HTTP 探测仍维持短超时，300 秒只扩大总准备窗口。

### 4.3 日志模型

- 复用 `IRecentLogBuffer` 作为 UI 单一日志流，增加宿主来源日志写入能力，不建立第二套相互漂移的集合。
- 宿主日志、stdout 和 stderr 使用明确来源；如现有 `ProcessOutputSource` 不适合宿主事件，扩展领域枚举或新增安装日志模型，而不是把宿主信息伪装成 stdout。
- 外部文本先通过 `OutputLineProcessor` 和脱敏器，再进入 UI 缓冲区。
- 关键阶段摘要通过 `ILogger` 写入滚动文件；禁止把完整 npm stderr 未经处理写入 Serilog。
- `RecentLogBuffer.Capacity = 1000` 与 `InstallationGuideViewModel.VisibleLogCapacity = 200` 当前是两个事实来源。阶段 0 基于真实 npm 输出冻结一个集中容量值，底层共享缓冲和安装 UI 都引用该值，并删除 ViewModel 的第二个较小常量，避免任一层提前淘汰。

### 4.4 计时模型

- 抽象可测试的单调时钟/周期计时能力，ViewModel 不直接依赖不可控的长延时。
- 计时状态同时包含操作总起始时刻、当前阶段起始时刻、总耗时和阶段耗时；阶段切换结算上一阶段并重置阶段起点，总起点保持不变。
- `InstallationGuideViewModel` 仅维护可绑定的阶段、阶段耗时、总耗时、期限文本和命令状态。
- 生命周期协调器继续决定操作完成、失败和取消；ViewModel 计时不能另建并行生命周期状态机。
- 每秒刷新属性，不每秒写日志；阶段切换和最终收尾才写日志。

### 4.5 手动操作服务

- 扩展或新增系统交互抽象，提供复制固定命令与打开可见 PowerShell 的能力。
- ViewModel 不直接使用 `Clipboard`、`Process.Start` 或 Shell 静态 API。
- PowerShell 只在已验证工作目录打开，不自动执行命令，不传入用户 Shell 文本。
- 官方链接继续由 `IExternalLinkLauncher` 的固定 `OfficialResource` 映射打开。
- 手动启动的 DSH 由健康检查识别为 `RunningExternal`，不进入 Job Object，不开放停止/重启。

## 8. 关键竞态与资源检查

以下场景必须使用可控替身、`TaskCompletionSource` 和有限测试超时，不依赖长时间 `Thread.Sleep`：

1. npx 输出到达与用户取消同时发生，取消后不追加过期成功状态。
2. 计时 tick 与 ViewModel Dispose 同时发生，释放后不访问 Dispatcher 或集合。
3. 进程立即退出发生在 PID 注册前，日志保留真实退出码且状态只提交一次。
4. 五分钟期限与健康确认同时完成，只允许一个终态，成功不被迟到超时覆盖。
5. 用户连续点击重试，只创建一个 npx 进程树。
6. PATH 重检与启动同时触发，resolver 使用与诊断一致的完整快照。
7. 手动外部服务出现时自动准备正在预检，不创建新 Owned DSH。
8. 日志缓冲淘汰最旧行时 UI 正在滚动，不抛跨线程异常或抢焦点。
9. 应用退出时计时器、事件订阅、operation CTS、Process、Job Object 和 DI 容器成对释放。

## 9. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| npm latest 引入破坏性 DSH | 参数、输出或身份标记变化导致启动失败 | 保持包名/参数边界；每次发布真实 latest 冒烟；身份失败拒绝加载并保留手动日志 |
| 5 分钟掩盖立即失败 | 用户无意义等待 | 进程退出立即失败；稳定 npm 错误即时映射；仅不可达等待使用总期限 |
| 详细日志泄露凭据 | npm/代理配置或 Token 泄露 | UI 前规范化、限长、脱敏；文件再次脱敏；专项测试 |
| PATH 合并引入不可信入口 | 命中恶意同名脚本 | 维持 Windows PATH 顺序和现有文件安全校验；日志仅显示安全摘要 |
| 每秒计时造成资源泄漏 | 关闭后回调 UI | 单操作 CTS、可释放周期计时器、Dispatcher 检查和竞态测试 |
| 自动滚动影响查看 | 用户无法复制早期错误 | 检测用户滚动状态，只在位于底部时跟随 |
| 手动终端被误认 Owned | 宿主错误停止用户进程 | 仅健康连接为 `RunningExternal`，无 PID 所有权不得停止 |
| 旧配置仍为 60 秒 | 升级用户问题未解决 | schema 显式迁移和真实升级测试 |
| 关于窗口保留固定版本模型 | UI 误导、死代码 | 重构 latest 信息模型并搜索清除现行固定版本文案 |
| 缺少干净 Windows 或网络限速环境 | 阶段 0/5 无法证明首次安装与超过 60 秒场景 | 将环境列为 minor 发布前置条件；缺失时明确阻塞整体发布，不以开发机缓存或自动化替代 |
