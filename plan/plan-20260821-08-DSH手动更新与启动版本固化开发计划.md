# DeepSeek Harness Desktop DSH 手动更新与启动版本固化开发计划

## 1. 计划信息

- 来源需求：[`prompt-20260821-08-DSH手动更新与启动版本固化需求.md`](../prompt/prompt-20260821-08-DSH手动更新与启动版本固化需求.md)
- 计划日期：2026-08-21
- 计划状态：开发完成（Desktop `0.10.2`）；外部 Windows/UI 验收待执行
- 实施基线 Desktop 代码版本：`0.10.1`
- 实施基线锁定 DSH：`0.1.0-rc.6`
- 目标锁定 DSH：`0.1.0-rc.7`
- 预计工期：4 至 6 个工作日，另加 npm/Windows 外部验证时间

本计划只形成方案，不修改代码、lockfile、发布物或应用版本。进入实现后才按仓库规则统一递增一次 Desktop patch 版本。

## 2. 实施结论

方案采用“手动更新 + 精确固化”，不实现动态 DSH 自动升级：

1. 用户仍在可见 PowerShell 手工执行固定 `npm install -g @deepseek-ai/dsh@0.1.0-rc.7`。
2. Desktop 下一代码版本把验证常量、package/lockfile、私有安装、缓存发现和 UI 固定到 rc.7。
3. Auto 在启动前验证全局 `dsh.cmd --version`，仅接受精确 rc.7；不匹配则回退私有/缓存 rc.7。
4. npm latest 继续只读，不进入配置、不动态改 lockfile、不自动执行 npm/npx。

当前 Desktop 可临时启动手工安装的全局 rc.7，但因为内部仍锁定 rc.6 且全局候选无精确版本门禁，只能用于人工验证，不能视为正式完成。

## 3. 关键取舍

### 3.1 为什么不能只替换一个版本常量

版本同时存在于代码常量、package.json、package-lock、私有 install/active 状态、缓存 manifest 校验、手动命令、测试和发布门禁。只替换常量会导致资源与代码不一致，发布脚本应当失败；只手工安装全局包则在 PATH 失效后仍回到 rc.6。

### 3.2 为什么不直接跟随 npm latest

仓库已有真实故障证明，范围型依赖漂移会产生混合依赖图并导致安装停滞。生产运行必须继续使用代码审查过的精确 lockfile；latest 只用于提示是否存在尚未验证的上游版本。

### 3.3 为什么全局候选也要验版本

现有发现逻辑找到 `dsh.cmd` 就优先返回，诊断虽执行 `--version`，但启动接受条件没有使用结果。若不修正，修改锁定版本后仍可能启动全局 rc.6、rc.8 或未知版本，无法满足“固化 rc.7”。

### 3.4 控制改动范围

- 复用现有 3 秒版本探测和 `CmdCommandLineBuilder`，只提取一个可测试的共享能力。
- 复用现有安装引导的复制命令和可见 PowerShell，不开发包管理器或版本选择器。
- 复用现有私有 staging、smoke、原子 active 指针和 release gate，不新建第二套安装系统。
- 不自动删除 rc.6，不改变 Custom/RunningExternal 语义。

## 8. 必测竞态

1. 全局版本探测期间用户取消或关闭窗口，探测进程必须退出且结果不覆盖新诊断。
2. 重新检查刚接受 rc.7 时 PATH 被外部修改，启动前必须重新发现或使用带身份/版本证据的不可变候选，不盲信旧路径。
3. 全局 rc.6 被拒绝与私有 rc.7 激活同时发生，最终只选择一个经过验证的候选。
4. rc.7 私有 smoke 成功与用户取消同时发生，只有完整提交或完整取消，不留下活动半成品。
5. 用户手工更新全局包时 Owned DSH 仍运行，Desktop 不结束手动 npm 进程；UI 明确要求先停止并在重新检查前不宣称完成。
6. npm latest 从 rc.7 变为 rc.8 时，正在运行或下一次 Auto 启动仍固定 rc.7。

## 9. 风险与控制

| 风险 | 控制 |
| --- | --- |
| rc.7 上游包或依赖图不可用 | 阶段 0 空 cache、真实启动、身份和回收硬门禁；失败继续 rc.6 |
| 只改常量造成 lock 漂移 | 常量/package/lock 三方门禁与完整发布验证 |
| 全局未知版本绕过固化 | 启动候选前执行有限时精确版本探测，不匹配继续回退 |
| 版本探测拖慢启动 | 只对 PATH 全局候选执行一次短超时探测；结果随本次不可变 discovery 返回 |
| 手动更新覆盖运行中文件 | UI 要求先停止 Owned DSH；Desktop 不并发执行 npm |
| 旧私有 rc.6 被误当 rc.7 | state version、lock hash、manifest 和 install id 共同验证 |
| latest 再次漂移 | latest 只读；生产版本和 lockfile 只能随代码评审发布 |
| 自动清理误删用户数据 | 本需求不新增旧版本自动删除，不触碰全局/npm 缓存 |


## 11. 完成定义

1. Prompt 的九项验收标准全部有对应证据。
2. rc.7 lockfile 经空 cache 真实安装和第二次免下载验证，不是只替换版本字符串。
3. Auto 启动的全局、私有和缓存候选都精确为 rc.7，错误全局候选不会遮挡正确回退。
4. 手动全局更新流程可用、可见、可取消，Desktop 不自动执行 npm 或提升权限。
5. latest 变化不改变验证版本和启动行为。
6. 现有 Owned/External、Job Object、loopback 身份、命令安全、隐私及轻量发布门禁全部通过。
7. 实现时的代码版本、manifest、版本历史、安装文档和验证记录一致；本次方案文档本身不触发版本递增。
